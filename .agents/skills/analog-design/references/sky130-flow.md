# SKY130 Analog Flow Reference

Use this reference when turning an analog request into repo actions.

## Flow Stages

1. Setup: verify `PDK_ROOT`, `PDK=sky130A`, and model files with
   `python3 scripts/check_tools.py`.
2. Primitive sanity: render or run `specs/primitive_nmos.yaml` before debugging
   a larger block when PDK setup is uncertain.
3. Schematic simulation: render from `specs/ota.yaml` and
   `circuits/ota/testbenches/ota_ac.spice.in`.
4. Measurement: parse ngspice `.measure` values into `measures.json`.
5. Multi-case evaluation: run `make eval-ota` for the named cases in
   `specs/ota.yaml`; inspect `circuits/ota/reports/latest_eval.md`.
6. Sizing: change device widths, lengths, multiplicities, and bias values in
   specs or through runner overrides.
7. Sweep: evaluate candidates with `scripts/sweep_ota.py`; compare `ranked_results.json` and `summary.md`.
8. Schematic capture: use Xschem once the netlist-level topology is stable.
9. Layout: use Magic/KLayout and keep DRC reports under `circuits/<block>/reports`.
10. LVS: compare extracted and schematic SPICE through Netgen.
11. PEX: generate extracted SPICE and repeat simulations against the original specs.

## Evidence Standards

Simulation evidence is a run directory containing:

- `effective_spec.yaml`
- `template_context.json`
- `rendered.spice`
- `ngspice.log`
- `measures.json`

Signoff evidence is a report file generated by the corresponding signoff script.
Do not claim signoff from manual inspection alone.

Evaluation evidence is:

- `circuits/ota/reports/latest_eval.md`
- `circuits/ota/sim/runs/eval/evaluation.json`
- per-case run directories containing rendered netlists, logs, and measures

## Sweep Practice

Use `make sweep-ota-quick` to smoke-test sweep logic. Use `make sweep-ota` or a
bounded `scripts/sweep_ota.py --max-candidates N` run for real design movement.
After choosing a candidate, apply it to the source spec and rerun `make sim-ota`.
Do not treat ignored sweep run directories as durable documentation; summarize
the decision in `circuits/<block>/reports/design_notes.md`.

## Push Practice

For long agentic work, commit and push after each coherent verified milestone.
Use a separate commit when a flow improvement is verified before moving on to
the next design or documentation step.
